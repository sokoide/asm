# Copy Benchmark: 同じ課題を 8 つの CPU で実装して比較する

`s13_copybench` は全アーキ共通の比較課題。100 バイトのメモリコピーを実装し、宛先の総和（チェックサム）を検証する。

## 課題仕様

- ソース: RAM 上の 100 バイト配列（バイト i = i、0〜99）
- コピー: src → dst に 100 バイト転送
- 検証: 宛先 100 バイトの総和を計算。正解は 0+1+...+99 = 4950 = `0x1356`
- 出力: `COPY OK CHECKSUM=1356`（失敗時 `COPY FAIL CHECKSUM=xxxx`）

## コピー本体の比較（この比較の核心）

コピー 1 バイトあたりの本体ループ。**命令の多様さ（CISC）と単純さ（RISC）の対比**がここに現れる。

| アーキ | 実装方式 | コピー 1 バイトあたり | 100 バイトのコピー本体 | 根拠 |
| :--- | :--- | :--- | :--- | :--- |
| 6502 | LDA abs,X / STA abs,X + INX ループ | 16 サイクル | 1599 サイクル | 6502 データシート（sim65 実測で検証可）。ソースに内訳記載 |
| Z80 | LDI + JP PE ループ | 26 T | 2600 T | simz80 T-state 表（go test で保証） |
| Z80 | （参考）LDIR: s101_blockops で実装 | 21 → 16 T/バイト | 2095 T（21×99+16） | 同上 |
| 8086 | REP MOVSB | 4.2 サイクル（17+4n） | 417 サイクル | 8086 タイミング表（isa CLI の clock 値）。ソースに内訳記載 |
| 68000 | MOVE.B (A0)+,(A1)+ + DBRA | 22 サイクル | 2238 サイクル（LEA/MOVE.W 含む） | MC68000 タイミング表。ソースに内訳記載 |
| PPC | LBZ/STB + CTR (bdnz) | 5 命令 | サイクル不測定 | スーパースケーラでコア依存のため |
| RISC-V | LBU/SB + ループ | 6 命令 | 同上 | 同上 |
| ARM64 | LDRB/STRB (post-index) + ループ | 4 命令 | 同上 | 同上 |

読みどころ:

- **Z80 の LDIR** は「1 命令でブロック転送」の極致だが、1 バイトあたり 16 T と 8086 の REP MOVSB（4 サイクル台）より遅い。命令は強力でも 1 バイトの実行コストは別の話
- **8086 の REP MOVSB** は本命のブロック転送。CISC のマイクロコードループはループのオーバーヘッドを命令の外に隠せる
- **6502 は abs,X インデックスの読み書きループで 1 バイト 16 サイクル**かかる。ポインタ間接 (zp),Y を使うとさらに重くなる。アドレス空間 64KB を 8 ビットレジスタの組合せで扱う構造的な重さ
- **RISC の RISC-V/ARM64/PPC は命令が単純**。ただし 1 命令あたりのサイクルはコア設計依存（パイプライン化で 1 バイト 1 サイクル以下になる）なので、この教材では**命令数**で比較しサイクル比較はしない
- **ARM64 の post-index writeback**（`LDRB w3, [x0], #1`）はポインタ更新をロードに統合し、ループ本体が 4 命令で最短

## シナリオ全体の計測

出力（チェックサム表示）を含むシナリオ全体の値。出力ヘルパの実装がアーキごとに異なるため、絶対値の直接比較には使えない。

| アーキ | コードサイズ (.text) | 実行命令数 (QEMU) | サイクル実測 | 計測方法 |
| :--- | :--- | :--- | :--- | :--- |
| 6502 | 85 バイト (+ helpers 92 バイト) | — | 15,428 サイクル | sim65 `-c`（正確な 6502 サイクル） |
| Z80 | 439 バイト (.com 全体) | 2,344 | 16,012 T | simz80 T-state 表（正確な Z80 タイミング） |
| x86_16 | 403 バイト | 1,114 | — | QEMU 命令数（サイクル非対応） |
| m68k | 462 バイト (データ 200 バイト含む) | 1,005 | — | 同上 |
| PPC | 574 バイト | 1,257 | — | 同上 |
| RISC-V 32 | 556 バイト | 1,436 | — | 同上 |
| RISC-V 64 | 560 バイト | 1,437 | — | 同上 |
| ARM64 | 432 バイト | 1,089 | — | 同上 |

## 計測方針

QEMU の実行時間は実機の CPU 性能比較に使えない（TCG はサイクル精度のエミュレーションではない）。この教材では以下の 3 系統で分ける:

1. **実測（正確なサイクルモデルを持つシミュレータ）**: 6502 = sim65、Z80 = simz80。`make cycles` で実測できる
2. **データシート計算**: 8086 / 68000。`isa x86_16 REP` / 68000 タイミング表に基づき、ソースコメントに命令ごとのサイクル内訳を記載して検証可能にする
3. **命令数のみ**: PPC / ARM64 / RISC-V。スーパースケーラ・キャッシュ・分岐予測で 1 命令あたりのサイクルがコア設計に依存するため、サイクル比較は意味を持たない
