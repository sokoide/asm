# Z80 アセンブリ学習教材 (CP/M シミュレータ)

Go 製 Z80 シミュレータ（simz80）上で動作する Z80 アセンブリ言語教材。CP/M BDOS 呼び出し規約を I/O に使い、共通 12 シナリオと拡張シナリオで段階的に学ぶ。加えて `common/c` の共通 C ソースを SDCC でアセンブリ化して観察する C シナリオ（C01/C02）を持つ。

## 前提条件

| ツール    | 用途                                | インストール                 |
| :---      | :---                                | :---                         |
| `z80asm`  | アセンブラ                          | `brew install z80asm`        |
| `simz80`  | Z80 + CP/M シミュレータ（Go 製）    | `go build -o simz80 main.go` |
| Go        | simz80 ビルド用                     | `brew install go`            |
| `sdcc`    | C コンパイラ（C シナリオ用。`sdasz80`/`makebin` を同梱） | `brew install sdcc` |

## ビルドと実行

```bash
# 全シナリオをビルド
make

# 特定のシナリオを simz80 で実行
make run S=s01_hello

# 全シナリオを連続実行（timeout 1 秒付き）
make runall

# 逆アセンブル（hex dump）
make dump S=s01_hello

# C シナリオ: common/c/c01.c を sdcc -S でアセンブリ化して実行
make build S=c01
make run S=c01
make debug S=c01

# CP/M 互換ファイルを cpm/ に生成（yaze-ag 用）
make cpm

# 掃除
make clean
```

### yaze-ag（CP/M 3.1 エミュレータ）での実行

[yaze-ag](https://github.com/andreasgerlich/yaze-ag) で実際の CP/M 環境上で .com を実行できる。

```bash
# 1. yaze-ag をインストール
brew install yaze-ag

# 2. yaze-ag ディスクイメージを ~/cpm/ に配置（初回のみ）
make cpm-setup

# 3. CP/M 互換ファイルをビルド
make cpm
```

CP/M のファイル名に `_` は使えないため、`make cpm` はアンダースコアを除去したコピーを `cpm/` に生成する：

| simz80 用          | CP/M 用 (cpm/)   |
| :---               | :---             |
| `s01_hello.com`    | `S01HELLO.com`   |
| `s02_registers.com`| `S02REGS.com`    |
| `s12_minishell.com`| `S12MSHL.com`    |

`.yazerc` 設定:

```text
mount a <yaze-ag-disks>/BOOT_UTILS.ydsk
mount b <yaze-ag-disks>/CPM3_SYS.ydsk
mount c <repo-root>/arch/z80/sim/cpm
go
```

実行例:

```text
$ yaze

A>c:s01
Hello, Z80 World!

A>e
```

## デバッグ

`make debug` / `make trace` / `make cycles` の 3 つのターゲットで simz80 の実行を観察できる。

```bash
# 対話ステッパー (simz80 -debug) で 1 命令ずつ実行
make debug S=s03_stack

# 全命令の実行トレースを非対話で表示（1 命令ごとに命令行 + 差分行）
make trace S=s03_stack

# 命令数と総 T-states を集計（4MHz 換算のミリ秒も表示）
make cycles S=s04_loops
```

`make debug` のステッパーは 1 命令ごとに「実行した命令の逆アセンブル行 + 変化したレジスタ（old→new）+ フラグ変化 + 消費 T-states」を表示する。逆アセンブルには z80asm の出力する `.lst` を利用する。BDOS のコンソール入力が発生すると `[INPUT]>` プロンプトが現れる。

C シナリオ（`make debug S=c01` / `S=c02`）は z80asm の `.lst` を持たないため、逆アセンブル行は生のバイト列（`0104  11 00 00 C9` の形式）になり、`d` コマンドの出力は空になる（`r` / `x ADDR` / ステップ表示で観察する）。シンボルは `build-c` がリンクの `.map` から抽出して生成する `.lbl`（`_add: equ $0104` 形式）から読み込まれ、`b _main` / `b _add` のシンボルブレークポイントが使える。

**ステッパーのコマンド**:

| コマンド   | 動作                                     |
| :---       | :---                                     |
| `s`        | 1 命令ステップ実行                       |
| `n`        | next（CALL 先に入らずに進む）            |
| `c`        | continue（次のブレークポイントまで実行） |
| `b ADDR\|SYM` | アドレス ADDR またはシンボル名（`b print_str`）にブレークポイント設定。シンボルはビルド時に出力される `.lbl`（z80asm `--label=`）から読み込む |
| `r`        | 全レジスタ表示                           |
| `d [ADDR\|SYM]` | 逆アセンブル表示                    |
| `x ADDR\|SYM`   | ADDR からメモリダンプ               |
| `q`        | 終了                                     |

**フラグ変化の表示例**: `LD A,7Fh` → `ADD A,01h` を実行すると (`make trace` の実出力):

```text
#2     T+7   Σ14     0102  C6 01       add a, 0x01
         A   7F → 80   F   00 → 94
         flags S 0→1  H 0→1  P/V 0→1
```

7Fh + 01h は符号付き 8-bit で +127 + 1 = -128 となり、S（符号）・H（半キャリー）・P/V（オーバーフロー）が立つ。この挙動は `make test` のユニットテストで検証している。

**T-states の精度**: `make cycles` の T-states 集計は正確な Z80 T-state 表に基づく（BDOS のホスト呼び出し部分は除外）。実機 Z80（4MHz）での実行時間の見積もりに使える。

## シナリオ一覧

### S01: Hello World

**難易度**: ★☆☆☆☆

最も基本的な CP/M プログラム。BDOS 関数 9（文字列出力）を使い、`$` 終端文字列をコンソールに出力する。

| 学習項目       | 説明                              |
| :---           | :---                              |
| `org 0x0100`   | CP/M プログラムの標準開始アドレス  |
| `ld c, 9`      | BDOS 関数番号を C レジスタに設定  |
| `ld de, msg`   | 文字列アドレスを DE レジスタに設定 |
| `call 0x0005`  | BDOS 呼び出し（CP/M システムコール）|
| `ret`          | CP/M に復帰（SP に積まれた 0x0000 に戻りシミュレータ停止）|
| `defm`         | 文字列定数の定義                  |
| `$` 終端       | BDOS fn 9 の文字列終端記号        |

**終了方法**: `RET` で CP/M に復帰（スタック上の 0x0000 に戻ると simz80 が停止）

> **コラム: CP/Mが作った$終端文字列の慣習──なぜnullじゃないのか**
>
> このリポジトリのZ80プログラムでは文字列を `$` で終端している。これはCP/MのBDOS関数9の規約による。
> Unix系のヌル終端（`\0`）やDOSとは異なり、CP/MはIntelのPL/Mコンパイラの文字列表現（`'...$'`）を継承したため
> `$` を終端記号に選んだと言われる。この慣習は後にMS-DOSの `INT 21h, fn 9` にも引き継がれた。

### S02: レジスタと算術

**難易度**: ★☆☆☆☆

Z80 の 8-bit レジスタ（A, B, C, D, E, H, L）と 16-bit レジスタペア（BC, DE, HL）の基本操作を学ぶ。16 進数表示サブルーチンも実装する。

| 学習項目           | 説明                                      |
| :---               | :---                                      |
| `ld a, n` / `ld r, r` | 即値・レジスタ間のデータ転送           |
| `add a, r`         | 8-bit 加算：A = A + r                     |
| `dec r` / `inc r`  | デクリメント・インクリメント             |
| `ld bc, nn`        | 16-bit 即値ロード                        |
| `add hl, bc`       | 16-bit 加算：HL = HL + BC                 |
| `inc hl`           | 16-bit インクリメント（0x00FF → 0x0100）  |
| `rrca` ×4          | A を右ローテート 4 回（上位ニブル取得）   |
| `and 0x0F`         | 下位ニブルのマスク抽出                   |
| `cp 10` → `jr c`   | 比較＋条件分岐（数字 vs A-F の判定）     |

**ポイント**: Z80 は `INC BC` / `DEC BC` も可能で、8-bit 同様に 16-bit のインクリメント・デクリメントが使える。

---

### S03: スタック操作

**難易度**: ★★☆☆☆

スタック（LIFO）の動作を理解し、`PUSH` / `POP` によるレジスタの保存・復元を学ぶ。ネストした PUSH/POP も実践する。

| 学習項目         | 説明                                          |
| :---             | :---                                          |
| `push af`        | AF レジスタペアをスタックに PUSH（SP -= 2）   |
| `push bc`        | BC レジスタペアをスタックに PUSH              |
| `pop bc`         | スタックから BC に POP（SP += 2）             |
| `pop af`         | スタックから AF に POP                        |
| LIFO             | Last In, First Out（最後に積んだものが最初に戻る）|
| ネスト PUSH/POP  | PUSH DE → PUSH HL → POP DE → POP DE で値の入れ替わりを確認 |

**ポイント**: Z80 では AF も PUSH/POP 可能。`PUSH AF` → `POP BC` のように異なるレジスタペアでも POP できる（値の移動に使える）。

---

### S04: ループ

**難易度**: ★★☆☆☆

`DJNZ`（デクリメント＋非ゼロ分岐）、`CP` + `JR NZ`（カウントアップ）、ネストループの 3 種類の反復処理を学ぶ。

| 学習項目                  | 説明                                      |
| :---                      | :---                                      |
| `djnz label`              | B--; B≠0 なら label へ相対ジャンプ        |
| `ld b, n` → `djnz`       | カウントダウンループの定石                |
| `cp n` → `jr nz, label`  | 比較＋非ゼロ分岐（カウントアップループ）  |
| ネストループ              | 外側ループ（C）+ 内側ループ（DJNZ）        |
| `push bc` / `pop bc`      | BDOS 呼び出し前後のカウンタ退避・復元     |

**ポイント**: BDOS 呼び出しは B レジスタを破壊するため、ループ内で BDOS を呼ぶ場合は `PUSH BC` / `POP BC` でカウンタを保護する必要がある。

---

### S05: 文字列操作

**難易度**: ★★☆☆☆

文字列の長さ測定（strlen）、`LDIR` によるブロックコピー（strcpy）、大文字変換を実装する。

| 学習項目             | 説明                                        |
| :---                 | :---                                        |
| `ld a, (hl)`         | HL の指すアドレスから 1 バイト読み込み      |
| `inc hl` / `inc de`  | ポインタのインクリメント                    |
| `cp '$'` → `jr z`    | 文字列終端（$）の検出                       |
| `cp 'a'` / `cp 'z'+1`| 範囲チェックによる小文字判定                |
| `sub 32`             | 小文字→大文字変換（ASCII 'a' - 'A' = 32）  |
| `ldir`               | ブロック転送：[DE]←[HL], HL++, DE++, BC--（BC>0 の間繰り返し）|
| `defs 32`            | 未初期化バッファ領域の確保                  |

**ポイント**: CP/M 環境では `$` を文字列終端に使う慣習がある（`defm` の BDOS fn 9 規約）。`LDIR` は Z80 の高速ブロック転送命令で、`LDI` を BC 回繰り返す。

---

### S06: シリアル入力

**難易度**: ★★★☆☆

BDOS 関数 1（コンソール入力）を使い、キーボードから文字を読み込む対話型プログラム。Enter キーで終了する。

| 学習項目           | 説明                                  |
| :---               | :---                                  |
| `ld c, 1`          | BDOS fn 1: コンソール入力（ブロッキング）|
| `call 0x0005`      | A レジスタに入力文字が返る            |
| `cp 13`            | CR（キャリッジリターン）判定          |
| `cp 10`            | LF（ラインフィード）判定              |
| `jr z, label`      | ゼロフラグによる条件分岐              |
| 入力ループ         | 文字受信 → 判定 → 継続/終了 のループ  |

**入力処理の流れ**:

1. `ld c, 1` で BDOS fn 1 を指定
2. `call 0x0005` でキー入力待ち（ブロッキング）
3. A レジスタに受信文字が格納される（BDOS が自動エコーバック）
4. CR/LF ならループ終了、それ以外は継続

---

### S07: サブルーチン

**難易度**: ★★★☆☆

`CALL` / `RET` による関数呼び出しと、レジスタ渡し・スタック渡しのパラメータ受け渡しを学ぶ。IX を使ったスタックフレームアクセスも実践する。

| 学習項目                    | 説明                                          |
| :---                        | :---                                          |
| `call label`                | サブルーチン呼び出し（戻りアドレスをスタックに PUSH）|
| `ret`                       | スタックから戻りアドレスを POP して復帰       |
| レジスタ渡し                | A, B レジスタで引数を受け渡し                 |
| ネスト CALL                 | サブルーチン内からさらにサブルーチンを呼ぶ    |
| `push` / `pop` による保存   | 呼び出し先でのレジスタ退避・復元             |
| `ld ix, 0` → `add ix, sp`  | IX をスタックフレームポインタとして使用       |
| `ld e, (ix+4)`              | スタック上の引数に IX+オフセットでアクセス   |

**Z80 サブルーチン呼び出し規約**:

| 項目       | 規約                                      |
| :---       | :---                                      |
| 引数渡し   | レジスタ（A, BC, DE, HL）またはスタック   |
| 戻り値     | A（8-bit）または HL（16-bit）             |
| 保存義務   | 呼び出し先で必要なレジスタを PUSH/POP で保存 |

---

### S08: ハードウェアアクセス

**難易度**: ★★★☆☆

BDOS 関数 12（CP/M バージョン番号取得）と、Z80 の `IN` / `OUT` 命令による I/O ポートアクセスを学ぶ。

| 学習項目           | 説明                                        |
| :---               | :---                                        |
| `ld c, 12`         | BDOS fn 12: CP/M バージョン番号取得         |
| `call 0x0005`      | HL にバージョン番号が返る（H=major, L=minor）|
| `out (n), a`       | 即値ポート n に A の値を出力                |
| `in a, (n)`        | 即値ポート n から A に読み込み              |
| `in a, (c)`        | レジスタ C で指定したポートから読み込み     |
| ポートアドレッシング | 即値（0x00-0xFF）または C レジスタ間接     |

**ポイント**: 本シミュレータでは I/O ポートはフローティングバスを模擬して 0xFF を返す。実機では各ポートが特定のハードウェアに対応する。

---

### S09: 条件分岐

**難易度**: ★★★★☆

`CP` 命令と各種条件分岐（`JR C/NC/Z/NZ`）を使った複数条件チェーンと、分岐テーブルパターンを学ぶ。

| 学習項目             | 説明                                      |
| :---                 | :---                                      |
| `cp n`               | A - n の減算結果をフラグに反映（A は不変）|
| `jr c, label`        | キャリーフラグ（C=1）で相対ジャンプ       |
| `jr nc, label`       | キャリーなし（C=0）で相対ジャンプ         |
| `jr z, label`        | ゼロフラグ（Z=1）で相対ジャンプ           |
| `jr nz, label`       | 非ゼロ（Z=0）で相対ジャンプ               |
| 複数条件チェーン     | CP → JR Z/NZ を連鎖させた if-else 構造    |
| 分岐テーブル         | CP → JR Z のチェーンでインデックス分岐    |
| `ex de, hl`          | DE ↔ HL の交換（print_str の引数切り替え） |

**CP 命令のフラグ変化**:

| 条件         | フラグ               | 使用する JR    |
| :---         | :---                 | :---           |
| A == n       | Z=1                  | `jr z`         |
| A != n       | Z=0                  | `jr nz`        |
| A < n（符号なし）| C=1              | `jr c`         |
| A >= n（符号なし）| C=0             | `jr nc`        |

---

### S10: ビット演算

**難易度**: ★★★★☆

`AND` / `OR` / `XOR` / `CPL` の論理演算と、`SLA` / `SRA` / `SRL` のシフト命令、`BIT` / `SET` / `RES` のビット操作を学ぶ。

| 学習項目         | 説明                                          |
| :---             | :---                                          |
| `and n`          | ビット単位の AND（マスク抽出）                |
| `or n`           | ビット単位の OR（ビット結合）                |
| `xor n`          | ビット単位の XOR（ビット反転）               |
| `cpl`            | A の全ビット反転（1 の補数）                  |
| `sla a`          | 左算術シフト（bit 7 → C, LSB=0）             |
| `sra a`          | 算術右シフト（MSB 維持、符号保持）            |
| `srl a`          | 論理右シフト（MSB=0）                         |
| `set n, r`       | レジスタの bit n を 1 にセット               |
| `res n, r`       | レジスタの bit n を 0 にクリア               |
| `bit n, r` → `jr nz` | ビットテスト（Z フラグに結果反映）        |

**応用例**:

- `and 0x0F`: 下位 4 ビットの抽出（ニブルマスク）
- `or 0x80`: 最上位ビットのセット
- `xor 0xFF`: 全ビット反転（2 の補数ではない）
- `sla a`: ×2 の高速乗算

---

### S11: メモリ操作

**難易度**: ★★★★☆

メモリへのブロック単位の書き込み（fill）、`LDIR` によるコピー、`CPIR` による検索、IX/IY を使ったインデックスアドレッシングを学ぶ。

| 学習項目              | 説明                                            |
| :---                  | :---                                            |
| `ld (hl), a` → `djnz` | ループによるメモリ fill の定石                  |
| `ldir`                | ブロック転送（HL→DE, BC バイト分）              |
| `cpir`                | ブロック検索（HL から BC バイト分、A の値を検索）|
| `ld ix, addr`         | IX に 16-bit アドレスをロード                   |
| `ld a, (ix+3)`        | IX + 3 のアドレスから読み込み                   |
| `ld (iy+3), a`        | IY + 3 のアドレスに書き込み                     |
| `defs 16`             | 16 バイトの未初期化バッファ確保                 |

**CPIR の動作**:

1. A と (HL) を比較
2. HL++, BC--（一致しなければ 1 に戻る）
3. 一致または BC=0 で終了（HL は一致バイトの次を指す）

### S12: ミニシェル（総合）

**難易度**: ★★★★★

BDOS 関数 10（バッファ入力）を使った対話型コマンドシェル。文字列比較によるコマンド解析と、REPL ループを実装する。

| 学習項目                | 説明                                      |
| :---                    | :---                                      |
| BDOS fn 10              | コンソール行入力（バッファ読み取り）      |

### S13: コピー比較ベンチ（Copy Bench）

**難易度**: ★★★☆☆

全アーキ共通の比較課題。100 バイト（バイト i = i）のメモリコピーを `LDI` + `JP PE` の手書きループで行い、宛先 100 バイトの和を 16 ビットチェックサムとして 16 進 4 桁で出力する。`LDIR` はあえて使わない（s101_blockops で扱う）。

| 学習項目                | 説明                                              |
| :---                    | :---                                              |
| `ldi` + `jp pe`         | LDI は Z フラグを変えないため P/V（BC≠0）で分岐  |
| 16 ビットチェックサム   | `add a, e` + `adc a, 0` でキャリ伝播             |
| `cp n` → `jr nz`        | 宛先を既知パターン（dst[i] = i）と照合            |
| `print_hex8` × 2        | 16 ビット値を 16 進 4 桁で出力                    |

正解チェックサム: 0+1+...+99 = 4950 = 1356h。最終出力は `COPY OK CHECKSUM=1356`（失敗時 `COPY FAIL CHECKSUM=xxxx`）。

コピー部の手計算: LDI 16 T + JP PE 10 T = 26 T/バイト → 100 バイトで 2600 T。

**学習カード（予測 → 観察 → 改造 → 考察）**:

- **STEP 1 予測**: LDI ループは 16 + 10 = 26 T/バイト。100 バイトのコピー本体が何 T になるか、また `make icount` の総命令数（CPU 命令のみ）は何命令になるか予測してから実行して比べる
- **STEP 2 観察**: `make cycles S=s13_copybench` の合計 T-states は**プログラム全体**（チェックサム照合ループと BDOS 出力を含む）で、コピー本体だけではない。コピー本体 2,600 T は `make trace S=s13_copybench` の累積 T-state でループ入口・出口の差分を取るか、ソースコメントの内訳と照合する。`make icount` は CPU 命令のみ（BDOS 呼び出しを含まない）
- **STEP 3 改造**: LDI ループを `LDIR` 1 命令に置き換えたとき、コピー本体が 2,600 T → 2,095 T に減ることを予測し、`s101_blockops` で実測して比べる
- **STEP 4 考察**: Z80 LDIR は 21 T/バイト。8086 REP MOVSB（17.09 クロック/バイト）とクロック数では僅差だが、実行時間（@4 MHz vs @5 MHz）ではどうか。[docs/copybench.md](../../../docs/copybench.md) で「サイクル数」と「実行時間」を区別して比較する

### S101: ブロック転送（LDIR vs LDI ループ）

**難易度**: ★★★★☆

同じ 100 バイトコピーを `LDIR` と `LDI` + `JP PE` 手書きループの 2 方法で実行し、結果とチェックサムを出力して T-state の違いを比較する。

| 学習項目              | 説明                                                    |
| :---                  | :---                                                    |
| `ldir`                | 21 T/バイト（最終バイト 16 T）→ 21×99+16 = 2095 T     |
| `ldi` + `jp pe` ループ | 16 + 10 = 26 T/バイト → 100 バイトで 2600 T          |
| T-state 比較          | LDIR は JP の 10 T を 5 T の繰り返し処理に置き換え、約 19% 高速 |
| `im 1` / `ei`         | 割り込みモードと IFF の設定                             |

**IM / IFF の観察**: `make debug S=s101_blockops` で `s`（ステップ）実行すると、`im 1` 実行時に `IM 00 → 01` の差分行が表示される。`r` コマンドのレジスタ表示で `IM=1 IFF1=true IFF2=true` を確認できる。本シナリオではフラグの観察のみを行い、実際の割り込み注入は S102（s102_interrupts）で実演する。

**OTIR を含めない理由**: simz80 は OTIR の命令デコードと T-state 計数は行うが、`portOut()` はポート 0x10 の INT ラインモデル（後述「simz80 の割り込みモデル」）以外は no-op、`portIn()` は 0xFF を返すフローティングバスの模擬のみで、ポートデバイスをエミュレートしない。そのため OTIR の転送は観測可能な効果がなく、本シナリオでは意図的にコードに含めていない。

**学習カード（予測 → 観察 → 改造 → 考察）**:

- **STEP 1 予測**: LDIR は 21 T/バイト（最終 16 T）、LDI+JP PE は 26 T/バイト。100 バイトで両者の差は何 T になるか予測してから実行して比べる
- **STEP 2 観察**: `make trace S=s101_blockops` で LDIR が内部で反復する様子（1 命令で 21 T ずつ進む）と、LDI ループの 2 命令の往復を見る。`make cycles` は両者を続けて実行するため、合計から片方だけの値を取りたい場合は trace の累積 T-state で区切る
- **STEP 3 改造**: 反復数を 100 → 1,000 に変えると、LDIR と LDI ループの差は何 T 増えるか予測する（1 バイトあたり 5 T の差 × バイト数）
- **STEP 4 考察**: LDIR が速いのは 1 バイト 21 T で済むから（LDI ループは 26 T）。1 命令で書ける強さと、マイクロコード内部で同じ仕事をしていることの両方を理解する

### S101: 裏レジスタ（Shadow Registers）

**難易度**: ★★☆☆☆

Z80 独自の裏レジスタ（alternate register set）と、`EXX` / `EX AF,AF'` による高速コンテキスト切り替えを学ぶ。

Z80 は「メイン」と「裏（shadow）」の 2 組のレジスタを持つ：

```text
 メイン:  A   F   B   C   D   E   H   L
   裏:  A'  F'  B'  C'  D'  E'  H'  L'
```

| 学習項目                | 説明                                          |
| :---                    | :---                                          |
| `exx`                   | BC↔BC', DE↔DE', HL↔HL' を同時に入れ替え（1 命令）|
| `ex af, af'`            | AF↔AF' を入れ替え                             |
| ISR コンテキスト保存    | EXX + EX AF,AF' の 2 命令で全レジスタ退避     |
| ISR コンテキスト復元    | EXX + EX AF,AF' の 2 命令で全レジスタ復元     |

**従来の PUSH/POP との比較**:

| 方法            | 命令数 | スタック使用量 | 実行速度 |
| :---            | :---   | :---           | :---     |
| PUSH/POP × 4    | 8 命令 | 8 バイト       | 遅い     |
| EXX + EX AF,AF' | **2 命令** | **0 バイト** | **高速** |

**注意**: IX, IY, SP には裏レジスタがない。また、裏レジスタは割り込みハンドラ（ISR）での高速コンテキスト保存が主な用途であり、通常のプログラミングでは使用に注意が必要。

**学習カード（予測 → 観察 → 改造 → 考察）**:

- **STEP 1 予測**: ISR で全レジスタを保存・復帰する場合、PUSH/POP 12 命令と EXX + EX AF,AF' の 2 命令では何 T 違うか予想する（PUSH rp = 11 T × 6 + POP = 10 T × 6 に対し EXX 4 + EX AF,AF' 4）
- **STEP 2 観察**: `make debug S=s101_shadow` で `exx` 実行前後の BC/DE/HL の old→new 差分を見る。Step 4 の ISR で裏レジスタが使われていることをステップ実行で確認する
- **STEP 3 改造**: ISR で EXX を使わず PUSH/POP で退避する版を書き、`make cycles` で T-state を比べる
- **STEP 4 考察**: 裏レジスタが「割り込みの高速コンテキスト保存」である理由。6502（レジスタ 3 個のみ、A/X/Y を手で退避）と比べて割り込み応答の設計思想がどう違うか

### S102: 割り込み（IM 0 / IM 1 / IM 2）

**難易度**: ★★★★☆

Z80 の 3 つの割り込みモードを simz80 の INT 注入（ポート 0x10 トリガ、後述「simz80 の割り込みモデル」）で実演する。各デモで `OUT (0x10),A` により INT を発生させ、ハンドラ突入 → メッセージ出力 → `RETI` で復帰までを観察する。

| 学習項目              | 説明                                                        |
| :---                  | :---                                                        |
| `ld i, a`             | IM 2 ベクタテーブルの上位アドレスを I レジスタに設定         |
| ベクタテーブル構築    | I=0x80 + ベクタバイト 0x80 → 0x8080 にハンドラアドレスを格納 |
| `im 0` / `im 1` / `im 2` | 割り込みモードの切り替え（デバッグ差分行 `IM 00 → 02` など）|
| `ei` / 割り込み受付   | IFF1=1 で次の命令境界で INT を受付、IFF1/IFF2 は受付時にクリア|
| ページゼロのパッチ    | 0x0038（IM 1）、0x0010（IM 0 の RST 10h）に実行時に `JP` を書き込み|
| `reti`                | IFF2 → IFF1 を復元して割り込みから復帰（デイジーチェーンに EOI 通知） |

**受付タイミングと応答 T-state**（`make cycles S=s102_interrupts` の合計に含まれる）:

| モード | 派遣方法                                  | 応答 T-state |
| :---   | :---                                      | :---         |
| IM 0   | デバイスが RST 10h を供給 → 0x0010        | 13 T         |
| IM 1   | 固定 RST 38h → 0x0038                     | 13 T         |
| IM 2   | (I << 8) とベクタバイトのビット結合で表参照 | 19 T        |

**デバッグでの観察**: `make debug S=s102_interrupts` で `b 0121`（最初の `OUT (0x10),A`）にブレークポイントを置き `c` → `s` でステップすると、割り込み受付が専用行として表示される:

```text
── #978  T+19 (total 7696) ──
0123  INT (IM 2): vector 8080 -> handler 0175
   IFF1 01 → 00   IFF2 01 → 00   SP  FFFD → FFFB
```

受付直前に `r` で `IM=2 IFF1=true IFF2=true` を確認し、受付行で IFF1/IFF2 が 1 → 0 になり SP が 2 減（戻り PC を PUSH）すること観察できる。

**CP/M との互換性**: ハンドラ置き場は 0x0010 と 0x0038。CP/M のページゼロで使うのは 0x0000（ウォームブート）と 0x0005（BDOS 入口）のみで、simz80 では 0x0010/0x0038 は空き RAM のため退避・復元なしでパッチできる。また simz80 の BDOS は PC=0x0005 のホスト呼び出しトラップなので、ハンドラ内から BDOS 出力（fn 2）を呼んでも安全（実機 CP/M では BDOS は非リエントラントなため ISR から直接呼んではいけない）。

**学習カード（予測 → 観察 → 改造 → 考察）**:

- **STEP 1 予測**: INT 応答の T-state は IM 0/1 = 13 T、IM 2 = 19 T。3 つのデモ全体の `make cycles` に合計何 T 上乗せされるか（13+13+19）を予測する
- **STEP 2 観察**: `make trace S=s102_interrupts` で `INT (IM 2): vector 8080 -> handler` の受付行と、受付直前の `IFF1 01 → 00` 差分を見る。`make debug` の `r` 表示で `IM=2 IFF1=true` の状態も確認する
- **STEP 3 改造**: ハンドラの `reti` を `retn` に変えても simz80 では同じ動作になる。これはデイジーチェーンが無いため — 実機では何が違うかを README の「simz80 の割り込みモデル」節で確認する
- **STEP 4 考察**: IM 2 のベクタテーブル（I レジスタ + デバイスのベクタバイト）が x86 の IVT とどう似ているか。`make icount` が BDOS 呼び出しと割り込み受付を含まない「CPU 命令のみ」の値である点も確認する

### C01/C02: C → アセンブリ (sdcc -mz80 -S)

**難易度**: ★☆☆☆☆

リポジトリ root の `common/c/` にある C ソースを `sdcc -mz80 --no-peep -S`（sdasz80 構文）でアセンブリに変換し、crt0_z80.s と一緒にアセンブル・リンクして simz80 で観察する。C01 は `main` だけの最小構成（生成コード 8 バイト）、C02 は関数呼び出し `add()` とローカル変数を含む。SDCC の Z80 出力は z80asm ではアセンブルできないため、SDCC 同梱の `sdasz80` / `sdldz80` / `makebin` を使う。生成された `build/z80/c01.s` は学習対象なのでビルド後に残り、`make clean` で削除される（生成先はリポジトリ root の `build/z80/` で本アーキ専用のため、他アーキのビルドと干渉しない）。

| 学習項目                                    | 説明                                                            |
| :---                                        | :---                                                            |
| `sdcc -mz80 --no-peep -S`                   | sdasz80 構文のアセンブリを生成。`--no-peep` でピーフホール後処理を無効化しコードジェネレータの素の出力を残す（sdcc に gcc `-O0` 相当の単一オプションはない） |
| `.area _CODE` など                          | ASXXXX 系リンカのセクション指定。z80asm の `org` とは書式が異なる |
| `sdasz80 -go`                               | SDCC 同梱アセンブラ。`-g` は未定義シンボル（`_main` など）を外部参照にするために必須 |
| `sdcc --no-std-crt0 --code-loc 0x0100`      | SDCC 標準 crt0 を外してリンク。`--code-loc 0x0100` で CP/M TPA 先頭に配置（sdcc の z80 既定は標準 crt0 用ページを空けた 0x0200） |
| `makebin -p -o 256`                         | ihx（0x0000 起点で書かれる）→ .com 変換。先頭 256 バイトを捨てて 0x0100 起点にする |
| crt0_z80.s                                  | `call _main` + `ret` のみ。SP は simz80 が 0xFFFD に設定済み（0x0000 をリターンアドレスとして積済み）なので設定しない |
| sdcccall(1) 呼び出し規約                    | 第 1 引数 → HL、第 2 引数 → DE、16-bit 戻り値 → DE（詳細は下記） |
| `.lbl` シンボル                             | build-c がリンクの `.map` から `_main`/`_add` を抽出。debug で `b _main` が使える |

**使い方**:

```bash
make build S=c01      # common/c/c01.c → build/z80/c01.s (sdasz80 構文) → c01.com
make run S=c01        # simz80 で実行（出力なし。main 復帰後 ret → 0x0000 で停止）
make debug S=c01      # 対話ステッパー（b _main / b _add のシンボルブレークポイント可）
make trace S=c01      # 全命令トレース（.lst がないため生バイト列表示）
make cycles S=c01     # T-states 集計（c01 全体で 47 T）
make icount S=c02     # 実行命令数（c02 全体で 25 命令）
make dump S=c01       # hexdump
make clean            # 生成物とともに build/z80/ を削除
```

**SDCC Z80 呼び出し規約（実生成物 c02.s からの観察）**: SDCC 4.6.0 の `-mz80` 既定は sdcccall(1)（レジスタ渡し）。`add(int a, int b)` は第 1 引数 a を HL、第 2 引数 b を DE で受け取り、本体は `add hl, de` + `ex de, hl` + `ret` の 3 命令だけ。呼び出し側は `ld de, #0x0001` / `ld hl, #0x0001` で引数を設定して `call _add` する。**16-bit 戻り値は DE に返る**——根拠は 3 つあり、(1) `_add` 末尾の `ex de, hl` が計算結果を HL から DE へ移す、(2) main 側は `pop hl`（保存していた a）+ `add hl, de`（b を加算）で戻り値を使う、(3) `make trace S=c02` で main 復帰時 `DE 0000` を観測できる（`c - 42 = 0`）。`c - 42` の 16-bit 減算は `add a, #0xd6`（0xd6 = -42）+ `adc a, #0xff` という下位/上位バイトの 2 段階で行われる。関数属性 `__sdcccall(0)` で旧来のスタック渡し規約（全引数をスタック、戻り値は HL）に切り替え可能。`int` は 16-bit（Z80 のネイティブワード）。S07 の手書き規約（戻り値は A または HL）とは異なるので混同しないこと。

**ポイント**: crt0 は `call _main` + `ret` の 4 バイトだけ。CP/M ではプログラム起動時に OS がスタックを用意する（simz80 は SP=0xFFFD に 0x0000 を積んで 0x0100 から実行）ため、crt0 が SP を設定する必要がない。main から `ret` するとスタック上の 0x0000 に戻り、simz80 がこれをトラップして終了する——手書きシナリオと同じ終了経路である。本 crt0 は GSINIT（static 変数の初期化ルーチン）を呼ばない最小構成で、c01/c02 は静的変数を持たないためこれで動く（初期化付き static 変数を使う C は要改造）。`--no-peep` がないとピーフホールルールが `ld de, #0x0001` + `ld hl, #0x0001` を `ld de, #0x0001` + `ld h, d` + `ld l, e` へ置換するなど出力が変わり、同じ C でも生成アセンブリの見た目が大きく変わる。UART/コンソール出力を持たないため C シナリオは runall に含めない（`make all` では c01/c02 もビルドされる）。

**学習カード（予測 → 観察 → 改造 → 考察）**:

- **STEP 1 予測**: `int main() { return 0; }` の戻り値 0 はどのレジスタに、何命令で設定されるか。`build/z80/c01.s` を開く前に予測し、`make dump S=c01` の 8 バイト（`CD 04 01 C9 11 00 00 C9`）と突き合わせる。
- **STEP 2 観察**: `make debug S=c01` で `b _main` → `c` → `s` と進め、`ld de,#0x0000` を確認する。`make debug S=c02` では `b _add` → `c` → `r` で第 1/第 2 引数が HL/DE に入ったことを確認し、`s` × 3 で `add hl, de`（HL 1→2）→ `ex de, hl`（戻り値を DE へ）→ `ret` を追う。ブレークポイントから `c` で continue すると同じアドレスで即座に止まる（既存ステッパーの仕様）ため、続きは `b _add` の再入力（トグル解除）や `n`（ステップオーバー）を使う。
- **STEP 3 改造**: crt0_z80.s の `ret` を `jp 0x0000`（CP/M ウォームブートの入口）に変えても終了挙動は同じになることを確認する。また Makefile の CFLAGS から `--no-peep` を外して再ビルドし、c02 の生成コードがどう変わるか（引数コピー命令の置換）を diff で比べる。
- **STEP 4 考察**: sdcccall(1) の「第 1 引数 HL、第 2 引数 DE、16-bit 戻り値 DE」は S07 の手書き規約（引数は A/BC/DE/HL またはスタック、戻り値 A または HL）とどこが違うか。戻り値が DE の場合、HL を自由に使いながら値を返せる利点と、A 単独では返せない 16-bit 値の扱いを考える。同じ `common/c/c01.c` から生成した他アーキ版（x86_16 など）の c01.s とスタックフレーム構造（Z80 は IX フレームなしでレジスタ渡しが完結する）を比較する。

## simz80 の割り込みモデル

simz80 は実デバイスを持たない教育用に、I/O ポート 0x10 を INT 要求のトリガとして割り込みラインをモデル化する（`cmd/simz80/main.go` の `portOut()` / `acceptInterrupt()`）。

| 項目           | 動作                                                                    |
| :---           | :---                                                                    |
| トリガ         | `OUT (0x10),A` — 書き込んだ値 A をベクタバイトとしてラッチし INT をアサート |
| 受付条件       | IFF1=1 のとき次の命令境界で受付（`DI` 中は要求が保留される）             |
| 受付動作       | 戻り PC を PUSH、IFF1/IFF2 をクリア、INT ラインを解除                    |
| IM 0           | データバス上のオペコード実行をエミュレート（固定で RST 10h を供給）      |
| IM 1           | RST 38h（0x0038 へジャンプ）                                             |
| IM 2           | ベクタ = (I << 8) とベクタバイトのビット結合のアドレスから 2 バイト読んでジャンプ |
| 復帰           | `RETI` を使用。IFF2 → IFF1 を復元して PC を POP し、外部デバイスに割り込み終了 (EOI) を通知する。`RETN` は NMI 復帰用で、simz80 にデイジーチェーンは無いため動作は同一だが、マスク可能割り込みの復帰は教材として RETI を使う |
| 応答 T-state   | IM 0/1 = 13 T、IM 2 = 19 T（`make cycles` / `make trace` の集計に含まれる）|

応答 T-state の根拠は Zilog Z80 CPU User Manual (UM0080) の割り込み応答シーケンス（IM 0/1 の M1 となる INT acknowledge サイクル 13 T、IM 2 のベクタ参照を含む 19 T）。

**既知の簡略化**:

- `EI` ディレイ（割り込み Window）は実装済み: `EI` 直後の 1 個の境界では受付をスキップし、次の 1 命令が完了した後の境界で受付する
- IM 0 で供給するオペコードは RST 10h 固定（実機はデバイスが任意のオペコードを供給できる）
- 1 回の `OUT (0x10),A` は 1 回の割り込み要求（エッジ的に要求をクリア）。再要求には再度 OUT する
- `HALT` 中の割り込みによるウェイクアップは未対応（`HALT` 後は停止したまま）
- 割り込み優先度チェーン（IEI/IEO）や NMI、バス要求（BUSRQ）は未実装
- ポートデコードは下位 8 ビット（`port & 0xFF == 0x10`）のみ

## I/O ルーチン

本教材は Z80 実機ではなく、**教材独自の CP/M シミュレータ `simz80`（`arch/z80/sim/cmd/simz80/main.go`）** 上で動作する。`simz80` は CP/M 2.2 の BDOS（Basic Disk Operating System）呼び出しを **互換サブセットとして再実装** したものであり、実機 CP/M そのものではない点に注意。I/O はすべて BDOS 関数呼び出し（`CALL 0x0005`）で行い、UART などのハードウェアを直接操作しない。

**呼出規約**:

| 項目     | 説明                                                                |
| :---     | :---                                                                |
| 呼び出し | レジスタ C に関数番号を設定し `CALL 0x0005`                         |
| 引数     | 関数により E または DE レジスタ                                     |
| 戻り値   | A または HL（関数による）                                           |
| 終了     | `RET` でスタック上の `0x0000` に戻ると `PC=0x0000` をトラップして停止 |

**BDOS 関数（`simz80` 実装状況付き）**:

| 関数番号 (C) | 機能               | 入力                   | 戻り値                                     | simz80 | 教材使用   |
| :---         | :---               | :---                   | :---                                       | :---   | :---       |
| 1            | コンソール入力     | なし                   | A = 入力文字（`& 0x7F`、エコー付き）       | 実装   | S06, S12   |
| 2            | コンソール出力     | E = 文字               | なし（`E & 0x7F` を出力）                  | 実装   | 全シナリオ |
| 6            | ダイレクトコンソール I/O | E = 文字 / `0xFF`（入力要求） | A = 文字 or 0（非ブロッキング） | **未実装**（A=`0xFF`） | 未使用 |
| 9            | 文字列出力         | DE = 文字列アドレス    | なし（`'$'` または NUL まで出力　※）       | 実装   | S01        |
| 10           | コンソール行入力   | DE = バッファアドレス  | バッファに格納（`buf[1]`=長さ）            | 実装   | S12        |
| 12           | バージョン番号取得 | なし                   | B=`0x00`, A=`0x22`, HL=`0x0022`（CP/M 2.2）| 実装   | S08        |
| その他       | —                  | —                      | A = `0xFF`（未実装関数の既定動作）         | 未実装 | —          |

※ 公式 CP/M の文字列終端は `'$'`（0x24）のみ。`simz80` は `'$'` と NUL（0x00）の両方を終端として扱う。

**fn 10 のバッファ形式**（`DE` が指すアドレス）:

| オフセット | 内容                                 |
| :---       | :---                                 |
| `buf[0]`   | 最大長（入力前にプログラムが設定）   |
| `buf[1]`   | 実際の入力長（`simz80` が設定）      |
| `buf[2..]` | 入力文字列（`simz80` が設定）        |

**BIOS 層について**: 実機 CP/M は BDOS（高レベル OS API）と BIOS（低レベルデバイスドライバ）の 2 層構造で、BIOS は `0x0000` のジャンプベクタ経由でアクセスする。本教材の `simz80` は **BIOS 層を実装せず、BDOS のみ** を提供する。通常の I/O は BDOS 経由で十分である。

**プログラム構造と終了**:

```asm
org 0x0100          ; CP/M の TPA（Transient Program Area）開始アドレス

_start:
    ; ... プログラム本体 ...
    ret             ; スタック上の 0x0000 に戻り PC=0x0000 をトラップ → 終了
```

`simz80` はプログラム起動時にスタックへ終了アドレス `0x0000` を積む。`_start` から `ret` すると `PC=0x0000` となり、これをトラップしてシミュレータが終了する。

**定義元**: 教材独自 `simz80`（`arch/z80/sim/cmd/simz80/main.go` の `bdosCall()`、fn 1/2/9/10/12 のみ実装）。実機 CP/M BDOS 仕様とは細部（終端文字・未実装関数の扱い）が異なる。

## 次のステップ

1. 各シナリオのソースを開き、コメントを読みながらコードを追う
2. `make dump S=s02_registers` で逆アセンブル結果を確認し、各命令の機械語を観察する
3. 即値や文字列を変更してビルド → 実行し、結果の変化を確認する
4. S09 の分岐テーブルに新しい選択肢を追加してみる
5. S12 をベースに新しいコマンド（例: `add`, `echo`）を追加してみる
6. [`../CPU.md`](../CPU.md) を参照しながら、使われていない命令（ブロック入出力 `INIR` / `OTIR` など）を試してみる
