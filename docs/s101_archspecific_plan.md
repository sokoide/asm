- Phase 2: ppc/riscv/arm64 の s101 シナリオ + `compare/copybench.md` → 完了
- 未決事項の決定: (1) ARM64 は軸 A・軸 B ともに含めた。(2) 既存シナリオの改名を実施した。(3) 割り込み系は観察まで（IM/IFF の debug 観察、simz80/sim65 の拡張は未実施）。(4) RISC-V ページングは未実施

### Phase 3 実施状況 (2026-11-14)

- **6502 IRQ/NMI**: cc65 の sim65 ソースを `6502/sim65/sim65src/` にベンダリング（CPU コアには本家の IRQRequest/NMIRequest が既存）し、割り込みトリガ MMIO（`$FFCC` = IRQ パルス、`$FFCE` = NMI パルス）を memory.c に追加した `sim65i` を make 時に自動ビルド。既存シナリオはシステム sim65 とサイクル数まで同一（s01 7648 / s04 17715 / s11 63320 / s13 15428）。`s103_irq_nmi` で IRQ 受付 / I フラグマスク → CLI 後の遅延配信（リクエストはラッチされる簡略化） / NMI の I 無視を実演。簡略化: トリガはエッジとして扱われ受付まで保持（実機のレベルトリガではデバイスがラインを下ろすと消失）
- **Z80 割り込み注入**: simz80 に INT ラインを実装（OUT (0x10), A が要求 + ベクタバイト供給）。応答 T-state は Zilog UM0080 どおり IM 0/1 = 13T、IM 2 = 19T（acceptInterrupt 内で設定）。`s102_interrupts` で IM 2（ベクタテーブル）/ IM 1（RST 38h）/ IM 0（RST 10h）を実演。EI ディレイなし・HALT ウェイクアップ未対応・NMI 未実装の簡略化を README に明記。受付は BDOS トラップ (PC=0x0005) / 終了 (PC=0x0000) より後の命令境界
- **simz80 バグ修正 2 件**: (1) `INC/DEC IX/IY`（DD/FD 23/2B）が INC/DEC HL として実行される（s101_blockops で回避済みだった）+ `INC/DEC (IX+d)` の誤実行、(2) **`ADD IX,rp`（DD 09/19/29/39）が `LD IX,nn` として実行される** — こちらは `s07_subroutines` が誤った結果 `stack(1234,5678) = 0043` を出力していた（正しくは `68AC`）ため修正し、既存シナリオの出力が 1 行だけ正しく変化した。go test に INC/DEC/ADD IX/IY と割り込み 11 テスト追加
- **RISC-V S-mode ページング**: `s102_paging`（rv32 = Sv32 2 段、rv64 = Sv39 leaf-at-level-2）。M-mode で PMP（2 つの 2GB NAPOT エントリ — 単一 4GB NAPOT は QEMU の rv32 NAPOT 計算で動かない実測あり。PMP エントリなしでは mret 自体が access fault）→ medeleg 0xB000（実測: bit 11 のみ RO）→ mstatus.MPP = **bit 11**（bit 8 は SPP）→ mret → satp 設定 + sfence.vma → identity map 下で動作 → 0x40000000 への load/store で scause 13/15 のページフォールト → sret で復帰
- 検証: 全 8 アーキ runall PASS、z80 `make test` PASS、markdownlint / textlint 0 エラー

## 目的

共通 12 シナリオは基礎学習に適しているが、CPU 特有の設計思想（ブロック転送命令、特権モード、例外フレーム、セグメンテーション等）が十分に現れていない。アーキ固有の「面白い命令」に踏み込むシナリオと、同一課題を複数 CPU で実装して比較する共通課題を追加する。

## シナリオ番号規約（新設）

| 番号帯 | 用途 |
| :--- | :--- |
| `s01`–`s12` | 全アーキ共通の 12 シナリオ（既存。変更しない） |
| `s13`–`s99` | 今後追加する**共通課題**の拡張。全アーキで同じ番号・同じ名前を使う |
| `s101`+ | **アーキ固有**の拡張シナリオ。番号はアーキごとの独立空間（001 番台と同様、他アーキと対応しない） |

s13 以降を共通課題用に予約するため、CPU 固有のものは 101 番から振る。

### 既存シナリオの扱い（要判断）

| 現状 | 提案 | 根拠 |
| :--- | :--- | :--- |
| `z80/sim/s13_shadow` | `s101_shadow` に改名 | 裏レジスタは Z80 固有であり、新規約では s101 帯 |
| `x86_16/qemu/s13_multisector` | 変更しない | ディスク I/O は CPU 固有ではなく、共通課題（s13 帯）の先行例と位置づけられる |
| `x86_16/qemu/s14_protected` | `s101_protected` に改名 | 32-bit プロテクトモードは x86 固有の話題 |

## 軸 A: アーキ固有シナリオ（s101+）

各アーキの次の空き番号から順に付与する。

| アーキ | シナリオ案 | 実現性 |
| :--- | :--- | :--- |
| 6502 | Zero Page 高速アクセス（アドレッシングモード別サイクル実測）、自己書き換えコード | ✅ 実測可。IRQ/NMI は sim65 に割り込み入力がないため、シミュレータ拡張が前提 → Phase 3 に切り出し |
| Z80 | LDIR/OTIR ブロック転送（T-state 実測）。IM 0/1/2 は「IM 設定 + make debug で IFF/IM 観察」まで。ベクタ割り込みの実演は simz80 に INT 注入拡張が必要 | ✅ / ⚠️ |
| x86_16 | セグメント計算（物理アドレス = seg×16 + off）、REP MOVSB とループの比較、割り込みベクタテーブル | ✅ QEMU 実行可（サイクルは手計算） |
| m68k | MOVEM 一括退避、TRAP → 例外スタックフレームの観察、スーパーバイザモード遷移 | ✅ QEMU の trace/debug で例外フレーム観察可 |
| PPC | bl/blr とリンクレジスタ、CR フィールド別条件分岐、tw/twi トラップ → SRR0/SRR1 による例外処理 | ✅ |
| RISC-V | CSR 読み書き（csrrw/mstatus/mepc）、ECALL → トラップハンドラ。ページングは M→S 遷移 + Sv32/Sv39 が必要で難易度が突出 | ✅ / ⚠️（ページングは別 Phase 推奨） |
| ARM64 | 条件実行（NZCV + csel）、LDP/STP、SVC + VBAR_EL1 | ✅（含めるかは未決） |

## 軸 B: 共通比較課題「100 バイトメモリコピー」（s13_copybench）

新規約の s13 帯を使う共通課題。全アーキで同じ名前 `sXX_copybench`（XX = 13）として実装する。

- 仕様は全アーキ統一: 100 バイトのメモリコピーを行い、コピー後にチェックサムを出力して正誤確認する
- 主対象はクラシック 4 アーキ（6502 / Z80 / 8086 / 68000）。ppc/arm64/riscv も実装する。「RISC では同じシンプルな命令の繰り返しになる」という対比自体が教材になるため
- 期待される実装の違い:
  - Z80: `LDIR`
  - 8086: `REP MOVSB`
  - 68000: `MOVE` + ループ（`DBRA`）
  - 6502: `LDA`/`STA` + インデックスレジスタ

### 比較指標と計測方法

QEMU の実行時間は実機 CPU 性能の比較に使えないため、実測とデータシート計算の 2 系統に分ける。

| 指標 | 計測方法 |
| :--- | :--- |
| コードサイズ | lst / dump からバイト数（全アーキ共通・確実） |
| 実行命令数 | make cycles（QEMU 系）、simz80/sim65 の実測 |
| サイクル数 | 下表のとおり |

| アーキ | サイクル数の根拠 |
| :--- | :--- |
| 6502 | sim65 実測（`-c` による正確なサイクル計数） |
| Z80 | simz80 T-state 実測（LDIR は 21/16 を go test で保証済み） |
| 8086 | isa CLI の clock 値に基づく手計算。ソースコメントに命令ごとの内訳を記載し検証可能にする |
| 68000 | 68000 タイミング表に基づく手計算。同上 |
| ppc / arm64 / riscv | 測らない。スーパースケーラ等でコア依存のため、命令数とコードサイズのみで比較し README に明記 |

- 成果物: `compare/copybench.md` に比較表 + 各実装の逆アセンブル対比。「QEMU の実行時間を性能比較に使わない」方針も明記する

## 実装フェーズ

1. **Phase 1**: `s13_copybench` + 6502/z80/x86_16/m68k の s101 シナリオ（既存ツールだけで完結）+ 既存シナリオの改名（s13_shadow / s14_protected）
2. **Phase 2**: ppc/riscv/arm64 の s101 シナリオ + `compare/copybench.md` 完成
3. **Phase 3（任意）**: simz80 割り込み注入（Z80 IM 2 実演）、sim65 の IRQ/NMI 対応、RISC-V S-mode ページング — いずれもシミュレータ側の作業を伴う

実装は sub agent 2 体並行の既存慣行に従う（例: Phase 1 は 6502+z80 / m68k+x86_16、Phase 2 は ppc+riscv / arm64）。
