# 8086 アセンブラ ワークショップ（QEMU フロッピーブート版）

QEMU フロッピーディスクイメージからリアルモードで起動し、16550 UART (COM1, I/O 0x3F8) を I/O に使う x86 16-bit ベアメタルアセンブリ言語教材。共通シナリオ S01-S12 に加え、共通比較課題（s13 帯）と x86 固有の拡張シナリオ（s101+ 帯）で段階的に学ぶ。`common/c` の C ソースを clang `-m16` でアセンブリに変換して観察する C シナリオ（c01+）もある。

## 前提条件

| ツール           | 用途                 | インストール例                |
| :---             | :---                 | :---                          |
| NASM             | アセンブラ           | `apt install nasm`            |
| ld.lld           | リンカ               | `apt install lld`             |
| QEMU (i386)      | エミュレータ         | `apt install qemu-system-x86` |

## ビルドと実行

```bash
# 全シナリオをビルド
make

# 特定のシナリオを QEMU で実行（1 秒のタイムアウト付き）
make run S=s01_hello

# 全シナリオを連続実行（S06/S12 は printf で入力自動送信）
make runall

# 逆アセンブル（16-bit コード）
make dump S=s01_hello

# 逆アセンブル（32-bit セクタ 2 以降、S104 用）
make dump32 S=s104_protected

# 掃除
make clean
```

## デバッグ

```bash
# QEMU を -S -gdb tcp:127.0.0.1:1234 で起動し gdb を接続（ステップ実行）
make debug S=s01_hello

# C シナリオ: common/c/c01.c を clang -m16 -S でアセンブリ生成してからステップ実行
# (-g 付きのため 0x7C00 到達後は break main / list / step で C ソース行が見える)
make debug S=c01

# 命令ごとの逆アセンブル + CPU 状態を s01_hello.trace に記録して less で閲覧
make trace S=s01_hello

# 実行命令数を集計 (実サイクルは make cycles が unsupported を表示)
make icount S=s01_hello
```

`make debug` では gdb の `si`（1 命令ステップ）/ `c`（続行）/ `b *ADDR`（ブレークポイント）/ `info registers` / `x/5i $pc` で観察する（gdb が必要: `brew install gdb`、ポートは `GDB_PORT` で変更可）。UART 出力はステップ実行の進行に応じて同じターミナルに表示される。x86_16 はシンボルを持たないフラットバイナリだが、gdb の i8086 モードで 0x7C00 に自動ブレークする。`make cycles` は QEMU TCG がサイクル精度のエミュレーションではないため `unsupported` を表示し、実行命令数は `make icount` で計測する。

`make debug` は、gdb 起動時に `debug.gdb` を `-x` で明示的に読み込む（`.gdbinit` の自動ロードは使わない）。`debug.gdb` には以下の設定と `regs16`/`regs32` マクロが定義されている。ターゲット記述には、このディレクトリにある `i8086.xml` と、その参照先の `i386-32bit.xml` を使う。

```gdb
set tdesc filename i8086.xml
set architecture i8086
set disassembly-flavor intel
```

2 つの XML は [mrexodia/x86-real-mode-bootloader](https://github.com/mrexodia/x86-real-mode-bootloader) から取得した。再取得する場合は、このディレクトリで実行する。

```bash
curl -LO https://raw.githubusercontent.com/mrexodia/x86-real-mode-bootloader/master/i8086.xml
curl -LO https://raw.githubusercontent.com/mrexodia/x86-real-mode-bootloader/master/i386-32bit.xml
```

自動表示やログ保存の使い方は、[GDB によるリモートデバッグ](../../../README.md#gdb-によるリモートデバッグ-qemu-系)を参照。

## CPU と実行環境

S01〜S13、S101〜S103 は `cpu 8086` で命令セットを制限する。`bits 16` はサイズの既定値を指定するだけで、CPU 命令を制限しない。S104 は `cpu 386` を指定し、80386 以降の命令と 32 ビットプロテクトモードを使う。

16 ビットリアルモードは CPU の動作モードであり、8086 ISA は使用可能な命令の範囲である。`qemu-system-i386` は 80386 以降の CPU 環境をエミュレートし、GDB の `i8086` 指定は表示・解釈の設定であって QEMU を 8086 に変えるものではない。QEMU の実行結果や命令数から 8086 実機のサイクル数は求められない。

`make` はビルド、`make runall` は出力の観察用である。`make test` は各シナリオの QEMU シリアル出力の主要な期待文字列を照合する。PIT の変動値は照合せず、全出力や実機互換性の保証ではない。QEMU は停止命令後も終了しないため、タイムアウトまでの出力を確認する。

## シナリオ一覧

### S01: Hello World

**難易度**: ★☆☆☆☆

最も基本的なブートセクタプログラム。16550 UART (COM1, I/O 0x3F8) に `"Hello, 8086 World!"` を出力して停止する。

| 学習項目                     | 説明                                                       |
| :---                         | :---                                                       |
| `bits 16`                    | オペランドとアドレスの既定サイズを 16 ビットに設定                            |
| セグメント初期化             | `DS`, `ES`, `SS` を 0 に設定                               |
| `mov sp, 0x7C00`             | スタックポインタをコード直下に配置                         |
| `lodsb`                      | `[DS:SI]` から 1 バイト読み込み、`SI` をインクリメント    |
| `uart_putc`（16550 ポーリング） | LSR (0x3FD) bit 5 (THRE) 待ち → THR (0x3F8) に書込み   |
| ブートシグネチャ             | `times 510-($-$$) db 0` + `dw 0xAA55`（512 バイトに収める） |
| `cli` + `hlt`                | 割り込み禁止 → CPU 停止（タイムアウトで QEMU 終了）       |

**QEMU 終了方法**: タイムアウト（`make run` は 1 秒後に強制終了）

### S02: レジスタと算術

**難易度**: ★☆☆☆☆

レジスタ間のデータ移動と四則演算を体験する。結果を 16 進数で表示するサブルーチンも導入。

| 学習項目                          | 説明                                            |
| :---                              | :---                                            |
| `mov`, `add`, `sub`, `inc`, `dec` | 基本算術命令                                    |
| `ah` / `al`                       | レジスタの上位・下位バイトへのアクセス          |
| レジスタコピー                    | `mov bx, ax` で値の複製                        |
| `print_hex16`                     | AX をニブル単位で ASCII 変換して 4 桁表示       |
| 16 進数表示（ニブル分解）         | `shr` + `and 0x0F` → 0-9/A-F の ASCII 化       |

**ポイント**: `mov ax, 0x1234` → `mov bx, ax` で BX も 0x1234 になる。

### S03: スタック操作

**難易度**: ★★☆☆☆

スタック（LIFO）の動作を理解する。PUSH/POP でデータを保存・復元するパターンを学ぶ。

| 学習項目             | 説明                                               |
| :---                 | :---                                               |
| `push` / `pop`       | スタックへの保存・復元（SP が ±2、16-bit 単位）    |
| LIFO                 | Last In, First Out（最後に入れたものが最初に出る） |
| レジスタ保存パターン | `push ax` → 作業 → `pop ax` で値を保護             |
| スタック成長方向     | 下方成長（SP が減少する）                          |
| `mov sp, 0x7C00`     | スタックポインタの初期化                           |

**ポイント**: `mov ax, 0x1234` / `push ax` → `mov ax, 0x5678` / `push ax` → `pop bx`（BX=0x5678）→ `pop ax`（AX=0x1234）で LIFO を実証。

### S04: ループと条件分岐

**難易度**: ★★☆☆☆

`LOOP` 命令と `CMP` + 条件ジャンプを使った反復処理。`TEST` 命令による偶数/奇数判定も学ぶ。

| 学習項目      | 説明                                          |
| :---          | :---                                          |
| `loop`        | CX を自動デクリメントし、CX≠0 ならジャンプ    |
| `cmp` + `jle` | 比較 → 条件付きジャンプ（カウントアップループ） |
| `test`        | AND を実行せずフラグだけ更新（偶数/奇数判定） |
| カウントダウン | `loop` で 5→1 を表示                         |
| カウントアップ | `inc cl` + `cmp cl, 6` + `jle` で 1→5 を表示 |

**ポイント**: `loop` は CX をデクリメントしてから判定する。CX=1 のときは 0 になってジャンプしない。

### S05: 文字列操作

**難易度**: ★★☆☆☆

8086 の文字列命令群と `REP` プレフィックスを学ぶ。文字列長測定、コピーを実装する。

| 学習項目        | 説明                                           |
| :---            | :---                                           |
| `lodsb`         | `[DS:SI]` → AL、SI++                          |
| `stosb`         | AL → `[ES:DI]`、DI++                          |
| `scasb`         | AL と `[ES:DI]` を比較、DI++                  |
| `rep` / `repne` | CX 回繰り返し（等しい/等しくない間）           |
| `cld`           | ディレクションフラグをクリア（SI/DI 増加方向） |
| `repne scasb`   | null 文字（AL=0）を検索して文字列長を測定     |
| `rep movsb`     | CX バイトを一括コピー                         |

**文字列長測定の手順**:

1. `mov di, greeting` — 検索開始アドレス
2. `xor al, al; mov cx, 0xFFFF` — null 検索
3. `repne scasb` — 検索実行
4. `0xFFFF - CX - 1` が文字数

### S06: シリアル入力

**難易度**: ★★★☆☆

16550 UART から文字を読み込み、エコーバックする対話型プログラム。Enter キーで終了。

| 学習項目              | 説明                                        |
| :---                  | :---                                        |
| `uart_getc`           | UART 受信サブルーチン                       |
| LSR (0x3FD) bit 0     | Data Ready — 1 = 受信データあり             |
| RBR (0x3F8) 読み込み  | `in al, dx` で受信データ取得                |
| ポーリングループ      | `in` → `test al, 0x01` → `jz` でデータ待ち |
| エコーバック          | 受信文字をそのまま `uart_putc` で出力       |
| Enter (CR/LF) 判定    | `cmp al, 13` / `cmp al, 10` で入力終了判定  |

**UART 受信の流れ**:

1. LSR (0x3FD) の bit 0 (Data Ready) をポーリング
2. Data Ready = 1 になったら RBR (0x3F8) から 1 バイト読み込み

**難易度**: ★★★☆☆

`CALL` / `RET` による関数呼び出しと、レジスタ経由のパラメータ渡しを学ぶ。

| 学習項目         | 説明                                                |
| :---             | :---                                                |
| `call` / `ret`   | リターンアドレスをスタックに保存・復元              |

| ネスト呼び出し   | サブルーチンからさらに `call` で別の関数を呼ぶ     |

| `print_dots`     | CX 個のドットを `loop` で出力（ネスト呼び出し例）  |

`print_str` は AX, BX, CX, DX, SI, DI, BP を個別に保存し、逆順に復元する。`pusha` / `popa` は 80186 以降の命令。

### S08: ハードウェアアクセス（8254 PIT）

**難易度**: ★★★☆☆

Intel 8254 PIT (Programmable Interval Timer) のカウンタ値を I/O ポート経由で読み取る。

| 学習項目               | 説明                                          |
| :---                   | :---                                          |
| PIT カウンタ 0         | I/O ポート 0x40（16-bit カウンタ値）          |
| PIT 制御レジスタ       | I/O ポート 0x43（カウンタラッチ指示）         |
| `out dx, al`           | 制御レジスタに `0x00` を書き込みカウンタ凍結  |
| `in al, dx`            | ローバイト → ハイバイトの順に読み取り         |
| 16-bit 値の再構成      | `mov bl, al`（lo）+ `mov bh, al`（hi）→ BX   |
| 2 回目の読み取り       | PIT が動作中（カウントダウン中）であることを確認 |

**PIT 読み取り手順**:

1. `mov al, 0x00` → `out 0x43, al` でカウンタ 0 をラッチ
2. `in al, 0x40` → BL（ローバイト）
3. `in al, 0x40` → BH（ハイバイト）

### S09: 条件分岐

**難易度**: ★★★★☆

`CMP` + 条件ジャンプを使った分岐処理を学ぶ。符号付き比較と符号なし比較の違いを体験する。

| 学習項目           | 説明                                          |
| :---               | :---                                          |
| `cmp`              | 2 つの値を比較（フラグのみ更新）              |
| `je` / `jne`       | ZF=1 で等しい / ZF=0 で等しくない             |
| `jl`（符号付き）    | SF≠OF のときジャンプ（less than）             |
| `jg`（符号付き）    | ZF=0 かつ SF=OF のときジャンプ（greater than） |
| 判定チェーン       | `cmp` → `jl` → `cmp` → `jg` で if-else 構築  |

**ポイント**: 42==42 → `je` で "Yes!"、-5 < 10 → `jl` で "Yes!"、30 > 10 → `jg` で "Yes!"。

### S10: ビット演算

**難易度**: ★★★★☆

AND / OR / XOR / SHL / SHR を使い、ビット単位の操作を理解する。2 進数表示サブルーチンも実装。

| 学習項目        | 説明                                                    |
| :---            | :---                                                    |
| `and`           | マスク抽出（`0x5A AND 0x0F = 0x0A`）                   |
| `or`            | ビット結合（`0x50 OR 0x0A = 0x5A`）                    |
| `xor`           | ビット反転（`0xFF XOR 0x0F = 0xF0`）                   |
| `xor ax, ax`    | レジスタのゼロ化（`mov ax, 0` より高速・短縮）          |
| `shl al, 1`     | 左論理シフト＝ ×2（`3 << 1 = 6`）                      |
| `shr al, 1`     | 右論理シフト＝ ÷2（`10 >> 1 = 5`）                     |
| `print_bin8`    | `shl` + キャリーフラグで 1 ビットずつ判定 → 2 進数表示 |

**2 進数表示の仕組み**: `shl al, 1` で最上位ビットをキャリーフラグに追い出し、`jc`/`jnc` で `'0'`/`'1'` を出力。

### S13: コピー比較ベンチ（全アーキ共通課題）

**難易度**: ★★★☆☆

全アーキテクチャ共通の比較課題。100 バイトのメモリコピーを `REP MOVSB` で行い、宛先 100 バイトの 8 ビットずつの総和（チェックサム）を 16 進 4 桁で出力する。QEMU はサイクルを測れないため、コピー本体のサイクル数は 8086 公開タイミング表に基づく手計算でソースコメントに記載している。

| 学習項目                  | 説明                                                        |
| :---                      | :---                                                        |
| `rep movsb`               | 1 命令で CX バイトを一括コピー（ループコード不要）          |
| コピー本体のサイクル手計算 | `REP MOVSB = 17 + 4×n`（n=100 → 417 サイクル）等をコメント記載 |
| 16 ビットチェックサム     | 0+1+...+99 = 4950 > 255 のため `add bl` + `adc bh, 0` で累算 |
| 正誤判定                  | 0x1356 と比較し `COPY OK CHECKSUM=1356` / `COPY FAIL CHECKSUM=xxxx` |

**実行出力**: `COPY OK CHECKSUM=1356`（1 行のみ）

**学習カード（予測 → 観察 → 改造 → 考察）**:

- **STEP 1 予測**: ソースコメントの手計算（コピー本体 1723 サイクル、`REP MOVSB = 9 + 17×100`）を読み、1 バイト当たり 17.09 クロックという数字を自分でも導いてから、`make icount S=s13_copybench` で総命令数を測る。REP MOVSB は 100 バイトを 1 命令として数えるので、命令数では極端に有利な点に注目する。
- **STEP 2 観察**: `make trace S=s13_copybench` で `rep movsb` が 1 行として現れる（内部の 100 反復は展開されない）ことを確認する。ICOUNT の内訳を見て、「命令数が少ない = 速い」ではないことを確認する（1 命令の実行時間が長い）。
- **STEP 3 改造**: `rep movsb` を `lodsb`/`stosb` + `loop` の手書きループに差し替える改造を設計し、icount と手計算サイクル（約 18 + ループオーバーヘッド/バイト）がどう変わるか予測してから試す。
- **STEP 4 考察**: `docs/copybench.md` を参照。Z80 `LDIR` 21T/バイト ÷ 4MHz と 8086 `REP MOVSB` 17.09 クロック/バイト ÷ 5MHz を時間で比較すると差が僅かになる — 「クロック数」と「実行時間」を区別する練習。

### S101: セグメントアドレッシング

**難易度**: ★★★☆☆

リアルモードのセグメント計算 `物理アドレス = seg×16 + off`（20 ビットアドレス）を実演する。同一物理アドレスを指す複数の seg:off ペア（エイリアス）と、オフセットの 64KB ラップアラウンドを説明する。

| 学習項目             | 説明                                                           |
| :---                 | :---                                                           |
| 物理アドレス計算     | `seg << 4`（SHL×4）+ オフセット + キャリー（ADC）で 20 ビット化 |
| エイリアス           | `0000:7C00` と `07C0:0000`、`1000:0023` と `1002:0003` が同一アドレス |
| 64KB ラップアラウンド | オフセットは 16 ビットで 0xFFFF → 0x0000 に折り返す（セグメント内） |
| ブート時の CS        | BIOS は `0x07C0:0000` か `0x0000:0x7C00` でジャンプする系統がある |

**実行出力**:

```text
physical = seg*16 + offset
0000:7C00 -> 07C00
07C0:0000 -> 07C00
1000:0023 -> 10023
1002:0003 -> 10023
Segment demo done
```

**学習カード（予測 → 観察 → 改造 → 考察）**:

- **STEP 1 予測**: `07C0:0000` と `0000:7C00` が同一物理アドレスになる式（0x07C0×16 = 0x7C00）を先に計算する。さらに `0xFFFF:0x0001` の物理アドレスは 20 ビットで表現できるか（1MB の壁とオフセットのラップアラウンドの違い）を予測する。
- **STEP 2 観察**: `make debug S=s101_segments` で 0x7C00 に自動ブレークするので、`si` で進みながら `print_pair` の `shl`/`adc` の実行前後でレジスタ（BX=seg, CX=off, 出力値）を `info registers` で追う。`make trace S=s101_segments` で 4 つのペア計算の流れを一覧するのも有効。
- **STEP 3 改造**: 新しいペア `0x1234:0x5678` の物理アドレスを手計算（0x12340 + 0x5678 = 0x179B8）してから、ソースに 5 番目のペアを追加して出力と突き合わせる。オフセット 0xFFFF の次のバイトが同じセグメントの 0x0000 に折り返す点も観察する。
- **STEP 4 考察**: m68k/RISC-V/ARM64/PPC はフラットアドレス空間（セグメント計算なし）。x86 16-bit だけが「16 ビットレジスタで 20 ビット空間を張る」技巧を必要とした歴史的理由（8086 のレジスタ幅とアドレスバス幅の不整合）を考察する。

### S102: 割り込みベクタテーブル

**難易度**: ★★★☆☆

IVT（割り込みベクタテーブル、物理 0x00000-0x003FF）にカスタムハンドラ（INT 60h）を登録し、ソフトウェア割り込みの入口と IRET による復帰を実演する。

| 学習項目                | 説明                                                              |
| :---                    | :---                                                              |
| IVT の構造              | ベクタ n のエントリは物理 `n*4`（オフセット word + セグメント word） |
| ハンドラ登録            | 0x60×4 = 0x0180 にハンドラの CS:IP を書き込む                     |
| `int 0x60`              | FLAGS/CS/IP をスタックに積み、IVT 経由でハンドラへ分岐            |
| `iret`                  | IP, CS, FLAGS を復帰して INT の次の命令へ戻る                     |
| ベクタ 0x60 の選択      | 0x00-0x1F は CPU/BIOS 予約。ユーザ定義は慣例上 0x60 以降          |

**実行出力**:

```text
Before INT 60h
  [INT 60h handler fired!]
Back after IRET
```

**学習カード（予測 → 観察 → 改造 → 考察）**:

- **STEP 1 予測**: `int 0x60` 実行時にスタックに積まれる 3 つの word（FLAGS, CS, IP）の順序と積まれる方向を先に書き出す。IVT エントリ 0x60 が物理 0x0180 に置かれる理由（0x60 × 4）も計算する。ソフトウェア割り込みは IF=0 でも動く — その理由（trap であり maskable interrupt でない）も予測する。
- **STEP 2 観察**: `make debug S=s102_vectors` で `int 0x60` のアドレス（`make dump S=s102_vectors` で確認）に `b *ADDR` を置き、`si` で突入時に `info registers` の SP とスタック内容（`x/3xw $ss:($sp)` 等）で FLAGS/CS/IP が積まれていることを確認する。`iret` で SP が 6 バイト戻ることも見る。
- **STEP 3 改造**: ベクタ 0x61 に 2 つ目のハンドラを登録して `int 0x61` を呼ぶ改造。IVT 書き込みアドレスが 0x0184 になることを予測してから試す。ハンドラ内で `push ax` を `pop ax` し忘れた場合、main 側でどう壊れるかも考察する。
- **STEP 4 考察**: m68k `TRAP #0`（ベクタ 32 は固定アドレス 0x80、フレームは SR+PC の 6 バイト）と x86 `INT 60h`（IVT、フレームは FLAGS+CS+IP の 6 バイト）は構造がよく似ている。RISC-V/PPC/ARM64 の「レジスタ渡し」への移行理由（フレームのメモリアクセス コスト）と並べて比較する。

### S103: マルチセクタ読み込み

**難易度**: ★★★★★

512 バイトの壁を超え、ディスクから追加セクタを読み込む。BIOS ディスクサービス (INT 0x13) を使用する。

| 学習項目             | 説明                                               |
| :---                 | :---                                               |
| `INT 0x13 AH=02h`    | ディスクからセクタを読み込みメモリに格納           |
| CHS アドレッシング   | Cylinder / Head / Sector でディスク位置を指定      |
| セクタ番号           | 1 始まり（セクタ 2 = オフセット 512 バイト目）     |
| `0x7E00`             | ブートセクタ直後のロード先（0x7C00 + 512）         |
| フラットバイナリ     | NASM `-f bin` + `ORG 0x7C00`（リンカ不使用）       |
| クロスセクタ実行     | `jmp 0x7E00` でセクタ 2 のコードに移行             |

**構造**:

```text
Sector 1 (0x7C00): ブートローダ
  ├── セグメント初期化
  ├── UART で "Loading..." 表示
  ├── INT 0x13 AH=02h（セクタ 2 読み込み, CL=2）
  └── JMP 0x7E00

Sector 2 (0x7E00): 読み込まれたコード
  ├── "Sector 2 loaded!" 表示
  ├── SP レジスタの値表示
  └── HLT
```

### S104: 32-bit プロテクトモード

**難易度**: ★★★★★

80386 以降を対象に、16-bit リアルモードから 32-bit プロテクトモードへ移行する。BIOS 割り込みが使えなくなり、全 I/O をポート直接アクセスで行う。

| 学習項目                      | 説明                                                               |
| :---                          | :---                                                               |
| GDT (Global Descriptor Table) | セグメントの属性（Base / Limit / 権限 / タイプ）を定義            |
| ヌルディスクリプタ            | GDT[0] = 0（CPU が要求）                                           |
| コードセグメント (0x08)       | Base=0, Limit=4GB, 32-bit, Exec/Read, Ring 0                       |
| データセグメント (0x10)       | Base=0, Limit=4GB, 32-bit, Read/Write, Ring 0                      |
| `lgdt [gdt_descriptor]`       | GDTR に GDT の位置とサイズをロード                                 |
| CR0.PE ビット                 | `mov eax, cr0` → `or eax, 1` → `mov cr0, eax` でプロテクトモード有効化 |
| ファージャンプ                | `jmp 0x08:pm_entry` でパイプラインをフラッシュ                     |
| セグメントセレクタ            | `mov ax, 0x10` → `mov ds/es/fs/gs/ss, ax`                         |
| 32-bit レジスタ               | EAX, ESI, EDI, ESP（16-bit の 32-bit 拡張版）                      |
| フラットメモリモデル          | Base=0, Limit=4GB（全メモリに線形アクセス）                        |
| I/O ポート継続使用            | `in`/`out` は CPL=0 で引き続き使用可能                             |

**プロテクトモード移行の手順**:

```text
1. CLI                    ← 割り込み禁止
2. LGDT [gdt_descriptor]  ← GDT を CPU に登録
3. MOV EAX, CR0           ← CR0 読み出し
4. OR EAX, 1              ← PE ビットをセット
5. MOV CR0, EAX           ← プロテクトモード有効化
6. JMP 0x08:pm_entry      ← ファージャンプ（16-bit キューをフラッシュ）
7. セグメントレジスタに 0x10（データセレクタ）を設定
   ↑ ここから 32-bit 命令が使える。BIOS 割り込みは使用不可。
```

**GDT の構造（各エントリ 8 バイト）**:

```text
Offset  Size  Field
  0      2    Limit[15:0]
  2      3    Base[23:0]
  5      1    Access Byte (P|DPL|S|Type)
  6      1    Flags (G|D/B|L|AVL) + Limit[19:16]
  7      1    Base[31:24]
```

**2 セクタ構造**: セクタ 1 に 16-bit ブートローダ + GDT、セクタ 2 に 32-bit PM コード。INT 0x13 でセクタ 2 を 0x7E00 にロード。

### C01/C02: C → アセンブリ (clang -m16 -S)

**難易度**: ★☆☆☆☆

リポジトリ root の `common/c/` にある C ソースを `clang -m16 -g -O0 -S`（`.code16` 出力）でアセンブリに変換し、crt0.asm と一緒にアセンブル・リンクして qemu + gdb で観察する。C01 は `main` だけの最小構成、C02 は関数呼び出し `add()` とローカル変数を含む。生成された `common/c/c01.s` は学習対象なのでビルド後に残り、`make clean` で削除される。ブートセクタは 512 バイトのため C コードも 510 バイト上限（超過時はビルドエラー）。

| 学習項目                     | 説明                                                            |
| :---                         | :---                                                            |
| `clang --target=i386-pc-none-elf -m16 -g -O0 -S` | `.code16`（16-bit リアルモード）のアセンブリを生成 |
| `66`/`67` プレフィックス     | 32-bit オペランド/アドレスを 16-bit モードで使うためのプレフィックス（`pushl` = `66 55` 等） |
| `calll`/`retd` ABI           | clang -m16 の関数呼び出しは 4 バイト戻りアドレス。crt0 は `o32 call main`（66 プレフィックス付き call）で呼ぶ |
| crt0.asm                     | DS/ES/SS=0、SP=0x7C00 のセグメント・スタック設定 + `o32 call main` + hlt |
| DWARF デバッグ情報           | `break *0x7c00` 到達後は `break main` / `list` / `step` で C ソース行単位のステップ実行 |

**使い方**:

```bash
make run S=c01        # QEMU で実行（UART 出力なし、HLT 到達で timeout 回収）
make dump S=c01       # crt0 + clang 生成コードの逆アセンブル (16-bit)
make debug S=c01      # qemu + gdb でステップ実行（C ソース行が見える）
make clean            # 生成物とともに common/c/c*.s を削除
```

**ポイント**: clang `-m16` の出力は 386 以降の命令（66/67 プレフィックス付き 32-bit オペランド）を含むため、QEMU の既定 CPU（qemu32）では動くが実 8086 では動かない。手書きシナリオ（`cpu 8086`）と命令セット前提が変わる点に注意。引数は x86_32 と同じスタック渡し（`8(%ebp)` 相当）だが 16-bit モードなので `67 66` の二重プレフィックスが付く。同じ `common/c/c01.c` から生成した x86_32/x86_64 版と `common/c/c01.s` を見比べると、モードごとの命令エンコーディングの違いが読み取れる。crt0 は UART 出力を持たず main 復帰後に `cli/hlt` で停止するため、C シナリオは runall に含めない。

**学習カード（予測 → 観察 → 改造 → 考察）**:

- **STEP 1 予測**: `common/c/c01.s` を開き、`main` のプロローグ（`pushl %ebp` = `66 55`、`movl %esp, %ebp`）と `movl $0, -4(%ebp)` が 16-bit モードでどうエンコードされるか（何バイト消費するか）先に予測する。
- **STEP 2 観察**: `make debug S=c01` で `break *0x7c00` → `break main` → `step` と進め、`x/5i $pc` で 66/67 プレフィックス付き命令を確認する。`make debug S=c02` では `break add` の 1 回目 `a=1 b=1`、2 回目 `a=20 b=20` を見る。`make dump S=c02` で `66 E8 rel32`（4 バイト戻りアドレスの call）と crt0 の `o32 call` が一致することも確認する。
- **STEP 3 改造**: `common/c/c01.c` に文字配列の初期化を追加して再ビルドし、`.rodata`/`.data` がイメージに加わって 510 バイト上限に近づく様子を `make build-c S=c01` の出力サイズで観察する。
- **STEP 4 考察**: `mov sp, 0x7C00` のスタックで 32-bit push（4 バイト単位）がどう SP を動かすかを gdb の regs16 で追う。実 8086 で動かすには何が不足するか（66/67 プレフィックス、`o32 call`）をソースと突き合わせて考える。

### 16550 UART (COM1)

| I/O ポート | レジスタ名 | 説明                                   | アクセス |
| :---       | :---       | :---                                   | :---     |
| `0x3F8`    | THR / RBR  | 送信保持 / 受信バッファ                | W / R    |
| `0x3FD`    | LSR        | ラインステータスレジスタ               | R        |

**LSR フラグビット**:

| ビット | 名前   | 説明                                   |
| :---   | :---   | :---                                   |
| 0      | DR     | Data Ready — 1 = 受信データあり         |
| 5      | THRE   | Transmitter Holding Register Empty — 1 = 送信可能 |

**送信手順**:

1. LSR (0x3FD) の bit 5 (THRE) をチェック
2. THRE = 1 になるまでポーリング (`in al, dx` → `test al, 0x20` → `jz`)
3. THR (0x3F8) に文字を書き込み (`out dx, al`)

**受信手順**:

1. LSR (0x3FD) の bit 0 (DR) をチェック
2. DR = 1 になるまでポーリング (`in al, dx` → `test al, 0x01` → `jz`)
3. RBR (0x3F8) から 1 バイト読み込み (`in al, dx`)

## I/O ルーチン

本教材は文字入出力に 16550 UART（COM1, `0x3F8`）の I/O ポートを直接操作する方針（「ハードウェア情報」の [16550 UART (COM1)](#16550-uart-com1) を参照）。BIOS 割り込み（`INT` 命令）は s103_multisector / s104_protected のディスク読み込みでのみ使用する。

**定義元**: QEMU が読み込む **SeaBIOS ROM**（QEMU i386 のデフォルトファームウェア）。`INT n` 命令を実行すると CPU がリアルモードの割り込みベクタテーブル（IVT, `0x0000`-`0x03FF`）を参照し、対応する SeaBIOS のハンドラへ分岐する。

**レジスタ規約（BIOS 共通）**: `AH` にサービス番号（機能）を設定し、その他のレジスタ（`AL`, `BX`, `CX`, `DX`, `ES:BX` 等）にパラメータを渡す。返り値は `AX`、エラー有無はキャリーフラグ `CF`（`CF=1` でエラー）。

**主な BIOS 割り込み**:

| 割り込み            | 機能             | 入力                                                                                   | 返り値                                       | 教材使用   |
| :---                | :---             | :---                                                                                   | :---                                         | :---       |
| `INT 0x10 AH=0Eh`   | テレタイプ出力   | `AL`=文字, `BH`=ページ番号                                                             | なし                                         | 未使用     |
| `INT 0x13 AH=02h`   | ディスクセクタ読込 | `AL`=セクタ数, `CH`=シリンダ下位, `CL`=セクタ(1-)/シリンダ上位2bit, `DH`=ヘッド, `DL`=ドライブ, `ES:BX`=バッファ | `AH`=ステータス, `CF`=エラー, `AL`=読込セクタ数 | **s103_multisector, s104_protected** |
| `INT 0x13 AH=00h`   | ディスクリセット | `DL`=ドライブ                                                                          | `AH`=ステータス, `CF`                        | 未使用     |
| `INT 0x16 AH=00h`   | キーボード入力   | なし                                                                                   | `AH`=スキャンコード, `AL`=ASCII              | 未使用     |
| `INT 0x1A AH=00h`   | システムタイマー読取 | なし                                                                                | `CX:DX`=ティック数, `AL`=midnight flag       | 未使用     |
| `INT 0x19`          | ブートストラップ | なし                                                                                   | 戻らない（再ブート）                         | 未使用     |

**使用例（ディスクセクタ読込）**:

```asm
mov  ah, 0x02        ; 機能: セクタ読込
mov  al, 1           ; 読込セクタ数
mov  ch, 0           ; シリンダ
mov  cl, 2           ; セクタ番号（1 始まり）
mov  dh, 0           ; ヘッド
mov  dl, 0x00        ; ドライブ（フロッピー）
mov  bx, 0x7E00      ; ES:BX = 転送先バッファ
int  0x13            ; 実行。CF=1 ならエラー
```

**注意**: BIOS 割り込みは **リアルモード（16-bit）でのみ使用可能**。IVT はリアルモード専用の構造であり、プロテクトモード（s104_protected の 32-bit 部）では IDT の再設定が必要なため BIOS を呼べない。教材はブート直後のリアルモード区間でセクタを読み込み、その後プロテクトモードへ移行する。
